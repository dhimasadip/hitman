# Database migrations

Migrations are checked-in, reviewed SQL generated by Drizzle Kit and applied by
`packages/database/src/migrate.ts`.

## Rules

1. Never edit an applied migration. Add a new forward migration.
2. Name/review for operational meaning; generated descriptive names are
   acceptable but the release must document the change.
3. Use expand/contract for rolling deploys: add nullable/defaulted structures,
   backfill, deploy code, then remove old structures in a later release.
4. Every migration must apply cleanly to an empty database and to staging.
5. Destructive migrations require a verified backup and an explicit rollback
   plan.
6. Migrations run as a separate one-shot deployment step before application
   rollout; application instances must not race each other.
7. Review constraints/indexes manually. Drizzle generation is a starting point,
   not a review.
8. Do not store plaintext secrets, raw webhook payloads, or unbounded bodies in
   migration-created columns.

## Commands

```bash
pnpm db:generate   # generate SQL from Drizzle schema
pnpm db:check      # collision/consistency check
pnpm db:migrate    # apply to DATABASE_URL
```

Current baseline:

- `0000_platform_baseline.sql` — creates `platform_schema_state`. This is an
  infrastructure migration proving the pipeline.
- `0001_identity_foundation.sql` — organizations, users, organization/team
  memberships, sessions, and audit events (Phase 4 / M001–M002 baseline).
- `0002_projects_and_gitlab.sql` — projects, project memberships, GitLab
  connections/repositories, and the audit project foreign key (Phase 5).
- `0003_api_catalog.sql` — OpenAPI specs/versions/operations, collections and
  folders, request definitions/versions, and source observation/link tables
  (Phase 6).

Environment, device, execution, and integration migrations begin in Phases 8–16
per `implementation-plan.md` §5.

## Rollback policy

Forward-fix is preferred. A schema rollback is allowed only when the migration
is non-destructive or a verified restore has been approved. Application rollback
alone must not require reversing a migration that has already been deployed.
